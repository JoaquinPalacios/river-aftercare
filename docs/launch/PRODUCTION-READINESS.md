# Production-readiness gate — River Aftercare

Living launch checklist based on **current repository truth** (Phase 2B). Classifications:

- **READY** — implemented locally and documented
- **REQUIRED BEFORE PRODUCTION** — must be true before a public production hostname serves clinics or patients
- **RECOMMENDED BEFORE FIRST PAYING CLINIC** — can wait for a design partner on staging, not for paid production use
- **POST-LAUNCH** — roadmap after first clinics

Do not provision Vercel, Cloudflare, R2, domains, or email from this document. Do not connect to the Neon project, run production migrations, or change Vercel `DATABASE_URL` from a documentation pass.

## First-client governance smoke (after ADR 0026 migrate + same-SHA redeploy)

Do **not** create a fake real clinic in production for this smoke unless Joaquín explicitly approves. Use existing demo data for sample/demo checks. Stop before inventing a production clinic.

Post-merge sequence remains: merge `main` → expected Vercel Production schema-gate failure while `20260920120000_add_sample_template_and_practice_attestation` is pending → `pnpm prod:db:status` → `pnpm prod:db:migrate --apply` → `pnpm prod:db:verify` → redeploy the **same merged SHA**.

Then:

1. Demo Dental still loads (`demodental` homepage).
2. Demo Extraction still behaves as sample/non-clinical (`isSample`, unreviewed, demo chrome). Do not mark it reviewed.
3. A real clinic template selector must not list the sample Extraction template. If no real clinic exists, skip and do not invent one.
4. Real clinic custom guide can draft and preview (`guideTemplateId` / `pinnedRevisionId` null).
5. Publish dialog requires the practice attestation checkbox.
6. Missing attestation cannot publish (server-side; draft and patient snapshot unchanged).
7. Attested publish succeeds and stores actor + timestamp on the new immutable revision.
8. Patient URL serves that exact published snapshot.
9. Edit after publish does not change the patient URL until republish.
10. Republish requires a fresh attestation; v1 attestation is not copied.
11. Clinic STAFF cannot publish or attest.
12. Patient pages do not show attestation identity, `reviewedBy`, or `MedicalWebPage`.

### Error tracking (Sentry)

River Aftercare sends **production application exceptions** to Sentry using `@sentry/nextjs`. This is not product analytics, session replay, or Better Stack Error Tracking. Better Stack remains the **uptime** product only. Alerting is **not** active until Joaquín creates the Sentry project and sets Vercel environment variables.

| Rule               | Detail                                                                                                                                                                                                                                                                                                                                                                                  |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Enablement         | Valid `NEXT_PUBLIC_SENTRY_DSN` (and/or server `SENTRY_DSN`) **and** `VERCEL_ENV` of `production` or `preview`. Production reports as `production`. Preview, if a DSN is added later, reports as `preview`. Development, test, and local: off even if a DSN is present. None of these variables are required for `pnpm build`.                                                           |
| Runtime            | Node.js `instrumentation.ts` + `sentry.server.config.ts` + Next.js `onRequestError`. Browser: `instrumentation-client.ts`. No Edge config: `proxy.ts` is Node-only in Next.js 16 and no production route sets `runtime = "edge"`.                                                                                                                                                       |
| Browser            | Initialized only when the public DSN is present on a Vercel production/preview build. Captures uncaught exceptions and React error-boundary failures. No Session Replay, no RUM beyond existing cookieless Vercel Analytics / Speed Insights, no user email/name attachment.                                                                                                            |
| Release            | Runtime `release` is `VERCEL_GIT_COMMIT_SHA` (client: `NEXT_PUBLIC_VERCEL_GIT_COMMIT_SHA`) when present; otherwise unset. Do not invent an application version.                                                                                                                                                                                                                         |
| Source maps        | `withSentryConfig` is wired. Upload happens only when `SENTRY_AUTH_TOKEN`, `SENTRY_ORG`, and `SENTRY_PROJECT` are all set at build time. Missing credentials skip upload and **must not** fail the build. Tokens are server/build-only — never `NEXT_PUBLIC_`. Status without those Vercel settings: **PARTIAL**.                                                                       |
| Privacy            | `sendDefaultPii: false`, `includeServerName: false`, `tracesSampleRate: 0`, `replaysSessionSampleRate: 0`, `maxBreadcrumbs: 0`, no local variables, attachments, module inventory, or device/OS/culture contexts. `beforeSend` removes user (including IP), headers, cookies, query, bodies, and **all URL fragments**. Staff email/name are not attached. Patient PII is not captured. |
| Operational events | Sanitized `contact_email_delivery_failed`, `auth_email_delivery_failed`, `auth_email_not_configured` only. Not validation, credentials, Turnstile, honeypot, expired/consumed tokens, 404s, authorization denial, or `/api/health`.                                                                                                                                                     |
| Session Replay     | **Intentionally disabled.** Staff screens and reset/invitation fragment URLs must not be recorded.                                                                                                                                                                                                                                                                                      |
| Tracing            | `tracesSampleRate: 0`, `profilesSampleRate: 0`, tracing tree-shaken from the client bundle. Not a performance-monitoring expansion.                                                                                                                                                                                                                                                     |
| Failure mode       | Missing DSN, Sentry outage, rejected events, or source-map upload failure must not fail a user request or `pnpm build`. Telemetry is never an availability dependency.                                                                                                                                                                                                                  |
| Verification       | After a Sentry DSN is set, a trusted machine may run `pnpm observability:test-error`. The CLI may read ignored `.env`; it does not require `VERCEL_ENV=production` and does not enable local app telemetry.
